## Issues Found

### Issue 1 (BUG, fixed): `RuntimeError` on every normal client disconnect

**Symptom.** Every clean disconnect logged
`main - ERROR - Unexpected error in streaming tasks` with a full traceback ending
in:

```text
RuntimeError: Cannot call "receive" once a disconnect message has been received.
```

**Root cause.** `upstream_task()` uses Starlette's low-level
`websocket.receive()`, which reports a client disconnect by *returning* a
`{"type": "websocket.disconnect"}` message rather than raising
`WebSocketDisconnect`. The loop therefore never exited, called `receive()` a
second time, and hit the `RuntimeError` — which fell through to the generic
`except Exception` handler instead of the `except WebSocketDisconnect` one.

**Fix** (`app/main.py`, in `upstream_task()`):

```python
message = await websocket.receive()

# The low-level receive() reports a client disconnect as a
# message rather than raising, so stop the loop explicitly.
# Calling receive() again after this would raise a RuntimeError.
if message["type"] == "websocket.disconnect":
    logger.debug("Client disconnected, stopping upstream_task")
    raise WebSocketDisconnect(message.get("code", 1000))
```

**Verification.** `test_t8_clean_teardown` asserts both
`Client disconnected, stopping upstream_task` and `Closing live_request_queue`
are present and that `Unexpected error in streaming tasks` /
`Cannot call "receive"` are absent. Browser teardown shows the same clean
sequence with zero ERROR lines.

## Frictions and Known Noise

### F1: shell environment shadowed `app/.env`

The first `test_t2` run failed with
`1008 policy violation: Publisher model .../locations/global/.../gemini-live-2.5-flash-native-audio was not found`.
Cause: the developer shell exports `GOOGLE_CLOUD_LOCATION=global`, and
`load_dotenv()` does **not** override pre-existing environment variables, so
`.env`'s `us-east1` was ignored.

Fixed permanently in the harness: `_dotenv_keys()` parses `app/.env` and
`_start_server()` strips every one of those keys from the inherited environment
before spawning uvicorn. The suite is now immune to developer shell leakage.

### F2: base64url without padding

`_audio_bytes()` initially raised `binascii.Error: Incorrect padding`. Pydantic's
`model_dump_json` emits `bytes` as **base64url without padding** (the data
contains `-` and `_`). The demo's own `app.js:785-795` `base64ToArray()` already
handles this correctly — only the test helper was wrong:

```python
def _b64_decode(data: str) -> bytes:
    """Decode the base64url-without-padding form Pydantic emits for bytes."""
    return base64.urlsafe_b64decode(data + "=" * (-len(data) % 4))
```

### F3: realtime image needs settle time

`test_t4` first returned "I didn't actually see an image." with a 0.5 s settle.
A three-way probe (1 frame/2 s, 5 frames/1 s, 10 frames/0 s) all returned "blue",
proving the path works — `send_realtime()` blobs are streamed rather than
turn-scoped, so they need to land before the `send_content()` turn opens. Settled
on 3 frames at 0.3 s plus a 2.0 s wait, which survives full-suite load.

### F4: `test_t5` assertion was initially too weak

`groundingMetadata` appears even on a plain "hello" turn, so it is not evidence
of a search. Tightened to `executableCode` / `functionCall` / `webSearchQueries` /
`groundingChunks`.

### F5: ADK 2.5.0 OpenTelemetry teardown noise (benign, not a demo bug)

Under the pytest harness, closing the `run_live()` generator from a different
asyncio context produces:

```text
opentelemetry.context - ERROR - Failed to detach context
ValueError: <Token ...> was created in a different Context
```

Originating in `google/adk/telemetry/_instrumentation.py:188` via
`google/adk/agents/base_agent.py:362`. Out of the demo's control, so `test_t8`
asserts only on demo-owned error strings and documents why in a comment. The
browser session did not trigger it at all (0 ERROR lines).

### F6: publisher-model REST probe is not a valid availability check

successfully. Only an actual `client.aio.live.connect` establishes availability.
This cost time while mapping the model/region table.
